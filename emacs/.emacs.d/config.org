* 初始化设置
:PROPERTIES:
:CUSTOM_ID: bootstrap
:END:

所有 Emacs 配置的第一步：设定包来源、安装包管理器、处理自定义变量。
这部分代码在所有其他模块之前执行，是配置的"地基"。

** 包管理器

Emacs 内置了 =package.el=，只需指定从哪里下载包。
三个源各有侧重：

| 源 | 地址 | 说明 |
|----|------|------|
| GNU ELPA | elpa.gnu.org | Emacs 官方维护，包最少但最稳定 |
| NonGNU ELPA | elpa.nongnu.org | 不开 GPL 但品质可靠的包 |
| MELPA | melpa.org | 社区最大源，几乎什么都有 |

=package-initialize= 加载已安装包的 autoload，让它们的关键函数可用。
=package-user-dir= 不显式指定时默认是 =~/.emacs.d/elpa/=。

#+begin_src emacs-lisp
(require 'package)
(setq package-archives
      '(("gnu"    . "https://elpa.gnu.org/packages/")
        ("nongnu" . "https://elpa.nongnu.org/nongnu/")
        ("melpa"  . "https://melpa.org/packages/")))
(package-initialize)
;; 确保 Emacs 能找到 Go 工具链（从桌面启动时 PATH 不完整）
(use-package exec-path-from-shell
  :ensure t
  :config
  (setq exec-path-from-shell-variables '("PATH" "MANPATH" "GOPATH" "GOMODCACHE"))
  (exec-path-from-shell-initialize))
#+end_src

** 垃圾回收优化（GC）

Emacs 默认的 GC 阈值只有 80KB，写代码时频繁触发垃圾回收会导致卡顿。
使用 =gcmh= 包动态管理：打字时不 GC，空闲时才悄悄回收。

| 设置 | 值 | 作用 |
|------|-----|------|
| =gc-cons-threshold= | 1GB | 开发期间几乎不 GC |
| =gcmh-high-cons-threshold= | 1GB | 打字时保持高阈值 |
| =gcmh-low-cons-threshold= | 200MB | 空闲时降到 200MB 触发清理 |
| =gcmh-idle-delay= | 15秒 | 停手 15 秒后才开始 GC |

#+begin_src emacs-lisp
;; 启动时设置高阈值，避免初始化期间的 GC
(setq gc-cons-threshold (* 1024 1024 1024))  ; 1GB

(use-package gcmh
  :ensure t
  :custom
  (gcmh-high-cons-threshold (* 1024 1024 1024))  ; 打字时 1GB
  (gcmh-low-cons-threshold (* 200 1024 1024))    ; 空闲时 200MB（清理更轻量）
  (gcmh-idle-delay 15)                           ; 空闲 15 秒后才开始 GC
  :init
  (gcmh-mode 1))
#+end_src

** use-package

=use-package= 是 Emacs 配置的事实标准。它的核心价值：
- 声明式语法：一个 =use-package= 块包含安装、加载、配置、快捷键
- 延迟加载：通过 =:defer= / =:commands= / =:mode= 等关键字控制加载时机
- 统一入口：不管包来自哪里，写法一致

|=:ensure t= 表示如果包未安装，自动从 MELPA 安装。
|这里设成 =nil=（默认不自动安装），每个需要安装的包显式写 =:ensure t=。
|干净环境第一次启动时，建议临时打开或改为 =t=，
|下载完所有包后再切回 =nil=，防止后续 MELPA 波动导致启动失败。

#+begin_src emacs-lisp
(unless (package-installed-p 'use-package)
  (package-refresh-contents)
  (package-install 'use-package))
(eval-when-compile
  (require 'use-package))
(setq use-package-always-ensure nil)
#+end_src

** 加载 custom.el

Emacs 的 =M-x customize= 界面会把设置自动写入 =custom-file=。
把它单独存放而不是混在 =config.org= 中，保持手写配置和自动生成配置的隔离。

#+begin_src emacs-lisp
(setq custom-file (expand-file-name "custom.el" user-emacs-directory))
(when (file-exists-p custom-file)
  (load custom-file))
#+end_src

** 界面元素

Emacs 默认显示工具栏、菜单栏、滚动条——这些在 GUI 下可以全部关掉，
把屏幕空间全留给内容。终端 Emacs 下它们本来就不显示。

=tool-bar-mode= / =menu-bar-mode= / =scroll-bar-mode= 各有一个 global minor mode，
参数 = -1= 表示关闭 .= -1= 表示关闭。

#+begin_src emacs-lisp
(scroll-bar-mode -1)        ; Disable visible scrollbar
(tool-bar-mode -1)          ; Disable the toolbar
(tooltip-mode -1)           ; Disable tooltips
(set-fringe-mode 10)        ; Give some breathing room
(menu-bar-mode -1)          ; Disable the menu bar
(setq visible-bell t)       ; Set up the visible bell
(setq inhibit-startup-screen t)        ; 跳过欢迎界面，直接进 scratch
(setq initial-scratch-message
      ";; Welcome singdile, let's do something.\n\n")
;; 解绑 C-\：系统级 fcitx5 用 C-\ 切换输入法，
;; Emacs 默认也绑了 C-\ 到 toggle-input-method，两者冲突。
;; 这里让 Emacs 让路，交给 fcitx5 处理。
(global-unset-key (kbd "C-\\"))
;; breadcrumb：顶部文件路径导航（eglot 同作者）
(use-package breadcrumb
  :ensure t
  :config
  (breadcrumb-mode 1)
  ;; 去掉边框和背景色，低调融入
  ;; 用 :inherit default 代替 (face-background 'default)
  ;; 前者在终端帧创建时能正常解析，后者在 daemon 启动时返回 "unspecified-bg"
  (set-face-attribute 'header-line nil
                      :box nil
                      :inherit 'default
                      :foreground "#7a7a7a"
                      :height 0.9))

让打字和编辑更顺畅的配置：补全、括号配对、搜索等。

** 补全框架

选择 Vertico + Corfu + Orderless 路线，各司其职：

| 包             | 职责                         | 工作位置                      |
|----------------+------------------------------+------------------------------|
| vertico        | 竖直展示补全候选               | minibuffer (M-x、C-x C-f 等) |
| marginalia     | 给候选加注释(文件大小,函数签名等) | minibuffer(vertico 的好搭档)  |
| orderless      | 灵活的匹配规则(支持空格分词,正则) | 全局生效                      |
| corfu          | 代码编辑器内的弹出补全框         | buffer 内(光标处)             |
| corfu-terminal | 终端 Emacs 下的 corfu 适配     | buffer 内(终端专用)           |

*** Vertico：竖直 minibuffer 补全

Emacs 默认的 =M-x= 只有一行，候选水平滚动。
=vertico= 把候选展开成竖直列表，一目了然。

两个自定义参数：

=vertico-cycle=：设为 =t= 后，候选列表首尾相连可以循环。
更重要的是：当零候选（比如打了一个不存在的文件名），
vertico 不会报错而是灰显输入，让你直接回车创建新文件。

#+begin_src emacs-lisp
(use-package vertico
  :ensure t
  :custom
  (vertico-cycle t)             ; 循环候选 + 零候选不报错
  :init
  (vertico-mode 1))
#+end_src

*** Orderless：智能模糊匹配

这是 Daniel Mendler（vertico/corfu/marginalia 的作者）推荐的
标准配置。核心策略：

- 对于 =M-x =、buffer 切换、变量补全：用 =orderless= 做子串匹配
- 对于 =C-x C-f= 文件补全：用 =partial-completion= 处理路径分隔符语义

=partial-completion= 的路径匹配规则：
把输入按 =/=、=.= 等分隔符拆成路径段，每段做前缀匹配。
- =~/.e → .emacs.d/ （=~= 展开后，=.e= 前缀匹配 =.emacs.d=）
- =e a = 空格分隔 → =e= 和 =a= 分别匹配不同路径段

对 =M-x= 等命令补全， =orderless= 继续生效：
- =inst pack= →  =package-install= （两词都找到）
- =!backup= → 排除含 backup 的候选

#+begin_src emacs-lisp
  (use-package orderless
    :ensure t
    :demand t
    :config
    ;; 补全样式：orderless 优先，basic 兜底
    (setq completion-styles '(orderless basic)
          completion-category-defaults nil
          completion-category-overrides
          '((file (styles partial-completion))))  ; 文件路径用 partial-completion
    ;; 按空格分词，# 转义
    (setq orderless-component-separator #'orderless-escapable-split-on-space))
#+end_src

*** Marginalia：给候选加注释

默认的 minibuffer 补全只有函数名，看不出它是做什么的。
=marginalia= 在右侧追加一行灰色小字：文件显示路径、函数显示签名、
变量显示当前值。

=marginalia-mode= 全局开启即可。

#+begin_src emacs-lisp
(use-package marginalia
  :ensure t
  :config
  (marginalia-mode 1))
#+end_src

*** Consult：增强版命令 + 实时预览

=consult= 是 Daniel Mendler 做的另一款工具，用新命令替换 Emacs
默认的几个搜索/跳转命令，全部集成 vertico，支持实时预览。

**代替原生命令的新快捷键：**

| 命令 | 快捷键 | 替代的原生命令 | 增强了什么 |
|--------|--------|---------------|------------|
| =consult-buffer= | =C-x b= | =switch-to-buffer= | 右边实时预览 buffer 内容 |
| =consult-line= | =M-s l= | =isearch= 的补充 | 用 vertico 竖直列表搜索当前文件 |
| =consult-ripgrep= | =M-s r= | =rgrep= | 异步搜索，结果带预览 |
| =consult-imenu= | 无（=M-x= 调用）| =imenu= | 文件大纲跳转，预览函数体 |
| =consult-goto-line= | =M-g g= | =goto-line= | 输行号时实时看到那一行 |
| =consult-find= | =M-s f= | =find-name-dired= | 按文件名搜索 |
| =consult-recent-file= | 无 | =recentf= | 最近文件，预览内容 |
| =consult-bookmark= | 无 | =bookmark-jump= | 跳转书签，预览 |

**工作原理：** consult 的所有命令都是对 =completing-read= 的包装。
候选列表由 vertico 展示，注释由 marginalia 追加。
三件工具无缝协作。

**=consult-customize=** 让某些命令预置参数。
这里让 =consult-buffer= / =consult-buffer-other-window=
在预览时忽略纯概念 buffer（=*= 开头的，如 =*Messages*=）。

#+begin_src emacs-lisp
(use-package consult
  :ensure t
  ;; 用 consult 命令替换原生命令的快捷键
  :bind (("C-x b" . consult-buffer)        ; 切换 buffer，带预览
         ("M-g g" . consult-goto-line)     ; 跳转到行，带预览
         ("M-g M-g" . consult-goto-line)   ; 同上（备用）
         ;; 在 search-map 下追加（M-s 前缀）
         :map search-map
         (("l" . consult-line)             ; M-s l：竖直列表搜索当前文件
          ("r" . consult-ripgrep)          ; M-s r：项目内递归搜索
          ("f" . consult-find))             ; M-s f：按文件名搜索
         ;; minibuffer 内：C-r 搜索历史（和 shell 习惯一致）
         :map minibuffer-local-map
         (("C-r" . consult-history)))       ; 从历史中搜索
  :custom
  ;; 预览相关
  (consult-preview-key 'any)               ; 任何键都触发预览（默认只部分键）
  ;; buffer 预览时忽略 * 开头的特殊 buffer
  (consult-buffer-filter
   '("\\` " "\\`\\*Customize" "\\`\\*Messages" "\\`\\*scratch"))
  :config
  ;; 预览时的样式
  (setq consult-preview-allowed-hooks '(global-font-lock-mode-hook
                                        rainbow-delimiters-mode-hook)))
#+end_src

*** Corfu：行内弹出补全

编写代码时，输入几个字符后自动弹出一个候选菜单，用 =M-n= /=M-p=
上下选择，=TAB= 或 =RET= 确认。

=corfu-auto=：开启自动弹出。输入一定字符数后自动弹出候选。
=corfu-auto-prefix=：输入多少字符后自动弹出（默认 3）。
=corfu-auto-delay=：暂停输入多少秒后弹出（默认 0，即立刻）。

=corfu-popupinfo-mode=：弹出的候选旁边再弹出一个详情窗口，
显示文档字符串/函数签名。类似 IDE 的悬浮文档。

#+begin_src emacs-lisp
(use-package corfu
  :ensure t
  :custom
  (corfu-auto t)                  ; 自动弹出补全
  (corfu-auto-prefix 2)           ; 输入 2 个字符后就弹出
  (corfu-auto-delay 0.05)         ; 停止输入 0.05 秒后弹出
  :config
  (global-corfu-mode 1)           ; 全局启用 corfu
  (corfu-popupinfo-mode 1))       ; 弹出详情
#+end_src

** helpful：增强帮助面板

原生 =C-h f= 查看函数时只显示一句话文档和源码链接。
=helpful= 接管这些命令，直接内联显示完整 Elisp 源码、
快捷键绑定列表、引用关系等。

尤其你还在搭建自己的配置——每写一个 =use-package= 块，
光标放在函数名上按 =C-h f= 立刻看到源码实现、所有绑定键。

**接管的关系：**

| 新快捷键 | 命令 | 替代的原生命令 | 增强了什么 |
|----------|------|---------------|------------|
| =C-h f= | =helpful-callable= | =describe-function= | 内联源码、快捷键、引用 |
| =C-h v= | =helpful-variable= | =describe-variable= | 语法高亮的值显示 |
| =C-h k= | =helpful-key= | =describe-key= | 显示该键对应的命令详情 |
| =C-h x= | =helpful-command= | — | 专看可交互命令（=M-x= 里的），含 keymap 信息 |

用 =C-h f= 查看 =consult-buffer= → helpful 直接展开 consult.el
的 Elisp 源码，不跳转、不翻页。

#+begin_src emacs-lisp
(use-package helpful
  :ensure t
  :bind (("C-h f" . helpful-callable)   ; 函数/宏
         ("C-h v" . helpful-variable)   ; 变量
         ("C-h k" . helpful-key)        ; 快捷键
         ("C-h x" . helpful-command)    ; 交互命令
         ("C-h q" . my/close-help-window)))  ; 关闭帮助窗口

;; 关闭帮助窗口而不影响其他窗口
;; 问题：C-x 1 会关闭所有其他窗口，C-x 0 需要移动光标
;; 解决：一键关闭帮助窗口，光标保持在原位置
(defun my/close-help-window ()
  "关闭帮助窗口，不影响其他窗口布局。"
  (interactive)
  (dolist (buf (buffer-list))
    (when (and (buffer-live-p buf)
               (with-current-buffer buf
                 (derived-mode-p 'help-mode 'helpful-mode 'Info-mode)))
      (when-let ((win (get-buffer-window buf)))
        (quit-window nil win)))))
#+end_src

** rainbow-delimiters：括号彩虹色

给不同嵌套深度的括号、方括号、花括号分配不同颜色。
一眼看出哪个 =)= 和哪个 =)= 配对，哪些括号层次没闭合。

编辑 Elisp（=config.org= 里大量括号）和 Go（=struct{}=、=fn()=）
时尤其有用。全用 =:custom= 设置，不需要手工调用 mode 函数——
=rainbow-delimiters-mode= 会在支持的编程模式中自动启用。

(use-package rainbow-delimiters
  :ensure t
  :custom

  :hook (prog-mode . rainbow-delimiters-mode))

* 项目管理
:PROPERTIES:
:CUSTOM_ID: projects
:END:

=projectile= 是 Emacs 里最流行的项目管理工具。一个"项目"就是
包含 =go.mod=、=.git= 或 =projectile= 标记文件的目录。
打开该目录下任意文件 → projectile 自动识别项目边界。

此后所有操作都在项目范围内进行：找文件只在项目内找、
切换 buffer 只列出项目内的 buffer、搜索只搜索项目目录。

**基本概念：**

- 不需要手动"打开项目"——打开项目目录下任意文件就自动激活
- =C-x p= 是 projectile 的命令前缀（Emacs 28+ 标准项目前缀）
- 所有子命令在 =C-x p= 后按单键触发
- 在 minibuffer 里仍然享受 vertico + orderless 补全

**常用操作：**

| 快捷键 | 命令 | 做什么 |
|--------|------|--------|
| =C-x p f= | =projectile-find-file= | 在项目内按文件名查找文件 |
| =C-x p b= | =projectile-switch-to-buffer= | 只在项目 buffer 间切换 |
| =C-x p d= | =projectile-find-dir= | 在项目内查找目录 |
| =C-x p p= | =projectile-switch-project= | 切换到另一个项目 |
| =C-x p s r= | =projectile-ripgrep= | 在项目内递归搜索文本（底层用 ripgrep） |
| =C-x p k= | =projectile-kill-buffers= | 关闭当前项目的所有 buffer |
| =C-x p ! = | =projectile-run-shell-command-in-root= | 在项目根目录执行 shell 命令 |
| =C-x p e= | =projectile-find-references= | 查找当前函数/变量的引用 |
| =C-x p R= | =projectile-replace= | 在项目内搜索并替换 |
| =C-x p t= | =projectile-toggle-between-implementation-and-test= | Go 文件 ↔ 测试文件切换 |

**项目类型自动检测：**

projectile 根据项目根目录的文件自动判断语言类型：
- 找到 =go.mod= → Go 项目
- 找到 =package.json= → Node.js 项目
- 找到 =.git= → 通用 git 项目

检测出的类型决定了某些命令的行为。
比如 Go 项目的 =C-c p t= 知道跳转到 =_test.go=。

**缓存：** projectile 首次打开项目时会扫描所有文件建索引，
几万文件的大项目可能慢一两秒。之后文件操作都是缓存即时响应。
如果新增了文件，=C-x p f= 里按 =C-u= 强制刷新缓存。

#+begin_src emacs-lisp
(use-package projectile
  :ensure t
  :diminish projectile-mode
  :config
  (projectile-mode 1)
  ;; 缓存设置
  (setq projectile-enable-caching t)     ; 启用文件索引缓存
  (setq projectile-indexing-method 'hybrid) ; 混合索引：git + 文件系统
  ;; 用 vertico/consult/marginalia 补全框架（你当前的配置栈）
  (setq projectile-completion-system 'auto))
#+end_src

* 版本控制（Magit）
:PROPERTIES:
:CUSTOM_ID: vc
:END:

Magit 是 Emacs 的 Git 客户端，不是一个 GUI wrapper——
它是一个让你在 Emacs 里用文本界面做所有 Git 操作的工具。

**和 shell 的区别：** git CLI 的操作粒度过大（=add . = → 全部提交），
magit 用区块/行级粒度操作：选中某一行代码、按 =s= 单独暂存。

**核心入口： =C-x g= **

按 =C-x g= 打开 magit 状态缓冲区，这就是你的"Git 仪表盘"。
这里显示当前仓库的：
- 未暂存修改（Unstaged changes）
- 已暂存修改（Staged changes）
- 最近的提交历史
- 未推送的提交
- 所有分支和 tag

**在 magit 状态缓冲区里的操作（单键）：**

| 键 | 命令 | 做什么 |
|----|------|--------|
| =g= | 刷新 | 刷新当前状态（等同于 =git status=） |
| =s= | stage | 暂存光标所在文件或区块 |
| =u= | unstage | 取消暂存 |
| =S= | stage all | 暂存所有修改 |
| =U= | unstage all | 取消所有暂存 |
| =c c= | commit | 提交已暂存的修改（弹出 commit message 编辑） |
| =c a= | amend | 修改上一次提交 |
| =p p= | push | 推送到远程 |
| =F u= | pull | 从远程拉取 |
| =b b= | checkout | 切换分支 |
| =b c= | new branch | 创建并切换到新分支 |
| =b l= | list branches | 查看所有分支（按 =RET= 切换） |
| =l l= | log | 查看完整提交历史 |
| =l o= | log current | 查看当前分支的提交历史 |
| =d d= | diff | 查看工作区与 HEAD 的差异 |
| =d s= | diff staged | 查看暂存区与 HEAD 的差异 |
| =k= | discard | 放弃光标所在处的修改 |
| =z z= | stash | 暂存工作区 |
| =z p= | stash pop | 恢复暂存 |
| =x= | reset | 软重置（保留工作区修改） |
| =q= | quit | 关闭 magit 缓冲区 |

**区块（hunk）级别的暂存：** 在 diff 视图里，光标放在任意行，
按 =s= 只暂存这一个修改区块——不需要 =git add -p= 那套交互式界面。
这是 magit 最让人上瘾的功能。

**和 projectile 的关系：** magit 自动识别当前仓库的根目录，
和 projectile 的项目边界一致。在一个 Go 项目里， =C-x p f=
找文件， =C-x g= 做 git 操作——两个前缀各司其职。

(use-package magit
  :ensure t
  :bind ("C-x g" . magit-status))  ; C-x g：社区事实标准
#+end_src

** org-modern：现代外观

=org-modern= 是 Daniel Mendler 维护的 Org 美化包，一次性替代
=org-superstar=、=org-bullets= 等多个老包。修改面的颜色而非
引入新字符，和 =modus-themes= 兼容极好。

它负责的视觉改进：
- 标题前缀（=*=）替换为漂亮符号（◉ ● ○ ◆ ►）
- 代码块、引用块加上现代边框（圆角、配色统一）
- 表格对齐线用细线渲染
- =TODO= / =DONE= 关键字用彩色标签
- 时间戳格式美化
- 列表 bullet 统一

以下子模块逐一开启（=org-modern= 默认不启用它们）：

=org-modern-block= ：代码块、例子块、引用块的现代渲染。
=org-modern-block-name= ：块的 =#+begin_src= 行标签样式。
=org-modern-checkbox= ：checkbox 勾选框美化。
=org-modern-horizontal-rule=：分隔线（=-----=）美化。
=org-modern-keyword=： =#+title=、=#+author= 等关键字淡显。
=org-modern-priority=： =#[A]= 优先级标签彩色圆角。
=org-modern-statistics=： =[1/3]= 进度统计美化。
=org-modern-table=：表格用 Unicode 细线绘制。
=org-modern-tag=：标签 =:tag:= 彩色圆角小胶囊。
=org-modern-timestamp=：时间戳 =<2024-01-01>= 美化。
=org-modern-todo=： =TODO= / =DONE= 彩色圆角标签。

** Agenda 显示优化

leuven-dark 主题默认将 agenda 的日期标题设为 1.6 倍字号
（=leuven-dark-scale-org-agenda-structure= 控制）。在周视图中，
当天的标题（蓝色底 + 大字）显得特别大而下面的任务项显得特别小，
比例失调。

下面从字号、网格、排序三个方向优化。

| 参数 | 作用 | 推荐值 |
|------|------|--------|
| 日期字号 | 从 1.6x 降到 1.2x，保持主题颜色 | =:height 1.2= |
| 区块标题 | =Agenda= / =Upcoming= 等段首文字 | =:height 1.15= |
| =org-agenda-prefix-format= | 每项前面显示分类、时间 | =%-12:c%= 分类 + =%-12t= 时间 |
| =org-agenda-time-grid= | 小时网格 + 当前时间指示 | 8:00-18:00 / =◀-- now= |
| =org-agenda-skip-*-if-done= | 已完成的不再显示在 deadline/scheduled 区 | =t= |

#+begin_src emacs-lisp
  ;; ---------- Agenda 显示优化 ----------

  ;; 1. 日期字号缩放到 1.2x（leuven 默认 1.6x 偏大）
  (dolist (face '(org-agenda-date org-agenda-date-today org-agenda-date-weekend))
    (set-face-attribute face nil :height 1.2))
  (set-face-attribute 'org-agenda-structure nil :height 1.15)

  ;; 2. 每项的显示格式
  ;;   %i = 缩进  %-12:c = 分类（左对齐 12 字符宽）
  ;;   %-12t = 时间  %s = 任务文本
  (setq org-agenda-prefix-format
        '((agenda . " %i %-12:c%?-12t% s")
          (todo   . " %i %-12:c")
          (tags   . " %i %-12:c")
          (search . " %i %-12:c")))

  ;; 3. 时间网格
  ;;   每天显示 8:00~18:00 的虚线网格，当前时间用箭头指示
  (setq org-agenda-current-time-string "◀-- now 现在")
  (setq org-agenda-time-grid
        '((daily today remove-match)
          (800 1000 1200 1400 1600 1800)
          " ╴" "╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴╴"))

  ;; 4. 区块分隔线
  (setq org-agenda-block-separator "─")

  ;; 5. 标签右对齐（负值表示右边缘到第 80 列，CJK 需要更宽）
  (setq org-agenda-tags-column -80)

  ;; 6. 已完成的任务不再出现在 deadline/scheduled 区
  (setq org-agenda-skip-deadline-if-done t)
  (setq org-agenda-skip-scheduled-if-done t)
  (setq org-agenda-skip-timestamp-if-done t)

  ;; 7. 子任务被阻塞时显示为暗淡
  (setq org-agenda-dim-blocked-tasks t)

  ;; 8. 排序：习惯优先 → 时间先后 → 优先级 → 分类
  (setq org-agenda-sorting-strategy
        '((agenda habit-down time-up user-defined-up priority-down category-keep)
          (todo   priority-down category-keep)
          (tags   priority-down category-keep)
          (search category-keep)))

  ;; 9. 窗口：在当前窗口打开，退出时恢复原样
  (setq org-agenda-window-setup 'current-window)
  (setq org-agenda-restore-windows-after-quit t)

  ;; 10. 默认视图：从今天开始的 7 天（不固定从周一开始）
  (setq org-agenda-start-on-weekday nil)
  (setq org-agenda-span 7)
  (setq org-agenda-start-day nil)

  ;; 11. 在 agenda 里用 C-c C-t 改状态时自动记日志
  (setq org-agenda-log-mode-items '(closed clock state))
#+end_src

** visual-fill-column：居中 + 换行

=visual-fill-column= 做两件事：把文本限在中间一栏 + 超长行自动折行。
折行是"视觉换行"——只在屏幕上换行显示，文件中还是完整的一行。
和 Microsoft Word 的自动换行逻辑一致。

想要 Word 级别的折行体验，还差一个细节：折行后的第二行缩进。
默认折行后第二行顶格开始，和上一行不对齐。=adaptive-wrap= 让
折行后的行自动保持和起始行同样的缩进级别。

例如一个列表项折行：
- 这是一段很长的文字，                  ← 第一行
  超长后自动折到这里，                  ← 自动折行（缩进对齐）
                                          而不是顶格

=visual-fill-column-mode= 内部已经启用了 =visual-line-mode=，
不需要手动加。

#+begin_src emacs-lisp
(use-package visual-fill-column
  :ensure t
  :custom
  (visual-fill-column-center-text t)   ; 文本居中
  (visual-fill-column-width 100))       ; 最大栏宽

(use-package adaptive-wrap
  :ensure t)

(use-package valign
  :ensure t
  :custom
  (valign-fancy-bar t))  ; 用 Unicode 细线替代默认的 | 和 -
#+end_src

** org-roam：双向链接笔记

=org-roam= 把你的笔记变成网状结构。每篇笔记是一个 Org 文件，
笔记之间用 =[[file:xxx.org][title]]= 链接。org-roam 自动追踪
反向链接——哪篇笔记引用了当前这篇，一目了然。

核心操作：

| 快捷键 | 命令 | 做什么 |
|--------|------|--------|
| =C-c n f= | =org-roam-node-find= | 查找/创建笔记 |
| =C-c n i= | =org-roam-node-insert= | 在当前位置插入到另一篇的链接 |
| =C-c n l= | =org-roam-buffer-toggle= | 打开/关闭反向链接侧栏 |
| =C-c n t=  | =org-roam-tag-add= | 给笔记加 tag |
| =C-c n a= | =org-roam-alias-add= | 给笔记加别名 |

=~/.emacs.d/org-roam.db= 自动创建——SQLite 数据库记录所有链接关系。
不需要手动维护。

#+begin_src emacs-lisp
(use-package org-roam
  :ensure t
  :custom
  (org-roam-directory (file-truename "~/org"))    ; 笔记根目录
  (org-roam-db-location "~/.emacs.d/org-roam.db") ; SQLite 数据库位置
  (org-roam-capture-templates
   '(("d" "default" plain "%?"
      :if-new (file+head "%<%Y%m%d%H%M%S>-${slug}.org"
                 "#+title: ${title}\n#+author: singdile\n#+date: %<%Y-%m-%d>\n\n")
      :unnarrowed t)))
  :config
  (org-roam-db-autosync-mode 1)                   ; 自动同步链接
  :bind (("C-c n f" . org-roam-node-find)
         ("C-c n i" . org-roam-node-insert)
         ("C-c n l" . org-roam-buffer-toggle)))
#+end_src

** org-format-inline-code：修复 =code= 前后空格

从外部复制文本到 Org 文件时，=code= 格式前后可能缺少空格，
导致 Org 无法正确识别为行内代码。

| 问题 | 修复后 |
|------|--------|
| 文字=code=文字 | 文字 =code= 文字 |
| 文字=code= 文字 | 文字 =code= 文字 |
| 文字 =code=文字 | 文字 =code= 文字 |

#+begin_src emacs-lisp
(defun my/org-fix-inline-code-spaces ()
  "为当前段落或选区的 =code= 前后添加缺失的空格。"
  (interactive)
  (let ((start (if (use-region-p) (region-beginning) (save-excursion (backward-paragraph) (point))))
        (end (if (use-region-p) (region-end) (save-excursion (forward-paragraph) (point)))))
    (save-excursion
      (goto-char start)
      ;; 匹配 =xxx= 格式，但不处理已有空格或处于行首/行尾的情况
      ;; 模式：非空白/行首 + = + 非空白内容 + = + 非空白/行尾
      (while (re-search-forward "=\\([^= \n\t]+\\)=" end t)
        (let ((match-start (match-beginning 0))
              (match-end (match-end 0))
              (code-content (match-string 1)))
          ;; 检查前面是否有空格或行首
          (unless (or (= match-start (point-min))
                      (memq (char-before match-start) '(?  ?\t ?\n)))
            (goto-char match-start)
            (insert " ")
            (setq match-end (1+ match-end)))
          ;; 检查后面是否有空格或行尾
          (unless (or (= match-end (point-max))
                      (memq (char-after match-end) '(?  ?\t ?\n)))
            (goto-char match-end)
            (insert " "))))))
  (message "已修复 =code= 前后空格"))
#+end_src

*** project 识别 Go modules

官方文档指出：Eglot 使用内置 =project= 包识别项目根目录，
但 =project= 默认不认识 Go modules。需要添加自定义 hook，

| 函数 | 作用 |
|------|------|
| =project-find-go-module= | 查找包含 go.mod 的目录 |

#+begin_src emacs-lisp
;; 让 project.el 识别 Go modules（官方推荐）
;; https://go.dev/gopls/editor/emacs
(require 'project)

(defun project-find-go-module (dir)
  "查找 Go module 根目录，排除 GOMODCACHE。
  
问题：如果打开 GOMODCACHE 中的依赖库，project.el 会把它识别为独立项目，
导致 eglot 启动新的 gopls 实例，而不是复用主项目的服务器。

解决：检测到 go.mod 在 GOMODCACHE 中时，返回 nil，不作为项目识别。
这样 eglot-extend-to-xref 就能让依赖库文件复用主项目的 gopls。"
  (when-let* ((root (locate-dominating-file dir "go.mod"))
              (truename (file-truename root)))
    (let ((gomodcache (or (getenv "GOMODCACHE")
                          (expand-file-name "pkg/mod"
                                            (or (getenv "GOPATH")
                                                (expand-file-name "~/go"))))))
      ;; 如果在 GOMODCACHE 中，不属于用户项目
      (unless (and gomodcache
                   (file-directory-p gomodcache)
                   (file-in-directory-p truename (file-truename gomodcache)))
        (cons 'go-module truename)))))

(cl-defmethod project-root ((project (head go-module)))
  "返回 Go module 项目的根目录。"
  (cdr project))

(add-hook 'project-find-functions #'project-find-go-module)
#+end_src

*** go-ts-mode + eglot

**核心原理：eglot-extend-to-xref 的工作机制**

当 =eglot-extend-to-xref = t= 时：

1. 用户在项目代码中执行 =M-.= (xref-find-definitions)
2. gopls 返回目标文件的 URI（可能是 =$GOMODCACHE= 或 =GOROOT=）
3. eglot 将该文件路径和**当前 gopls 服务器**存入 =eglot--servers-by-xrefed-file= 哈希表
4. 打开跳转后的文件时，eglot 检查该哈希表，自动复用原有的 gopls
5. 结果：在依赖库/标准库中获得完整的 LSP 功能

**为什么不能用自定义阻止逻辑？**

之前的 =my/go-eglot-ensure= 会主动阻止依赖库启动 eglot，
这破坏了 =eglot-extend-to-xref= 的机制，
导致跳转到依赖库后无法继续跳转。

**正确做法：直接使用 =eglot-ensure=**

让 eglot 的内置机制自动处理跨项目跳转，
配合 =project-find-go-module= 排除 GOMODCACHE，
确保依赖库不会启动新的 gopls 实例。

#+begin_src emacs-lisp
(use-package go-ts-mode
  :ensure nil
  :mode ("\\.go\\'" . go-ts-mode)     ; .go 文件自动用 go-ts-mode
  :hook (go-ts-mode . eglot-ensure)   ; 官方推荐，让 eglot-extend-to-xref 自动处理
  :custom
  (go-ts-mode-indent-offset 4))
#+end_src

** eglot：LSP 客户端（基础配置）

=eglot= 是 Emacs 29+ 内置的 LSP 客户端。以下配置适用于所有语言——
只设全局参数，不绑定到具体语言。

**核心设置说明：**

| 设置                       | 值       | 作用                              |
|----------------------------+----------+-----------------------------------|
| =eglot-request-timeout=    | 120      | 大项目首次索引时避免 Timeout              |
| =eglot-events-buffer-size= | 2000000  | 事件日志 2MB，出问题时能排查              |
| =eglot-autoshutdown=       | nil      | 不自动关闭（用自定义函数管理资源）     |
| =eglot-send-changes-idle-time= | 0.2  | 同步代码延迟，快速送达 LSP（默认 0.5s）    |
| =eglot-extend-to-xref=     | t        | **关键**：让跳转到依赖/标准库时复用当前 gopls |

**为什么 =eglot-autoshutdown = nil=？**

默认的 =autoshutdown= 会在关闭最后一个项目 buffer 时关闭 gopls，
但这会导致：
- 如果通过 xref 跳转到依赖库，关闭主项目 buffer 后 gopls 会被关闭
- 依赖库的 buffer 失去 LSP 支持

解决方案：
- 关闭自动关闭，用自定义函数 =my/eglot-cleanup-xref-servers= 管理资源
- 在关闭 buffer 时检查是否还有其他 buffer 在使用同一个 gopls
- 如果没有，才释放资源

**gopls workspace 配置关键参数：**

| 参数                   | 推荐值         | 说明                              |
|------------------------+----------------+-----------------------------------|
| =directoryFilters=     | 排除无关目录    | 减少索引负担，加速启动              |
| =diagnosticsDelay=     | "500ms"        | 诊断延迟，平衡响应和性能            |
| =completeUnimported=   | t              | 补全未导入的包                    |
| =deepCompletion=       | t              | 深度补全（可选，可能影响性能）        |
| =usePlaceholders=      | t              | 补全时显示 ${1:placeholder}       |
| =staticcheck=          | t              | 启用 staticcheck 静态分析          |
| =matcher=              | "Fuzzy"        | Fuzzy 匹配（比 CaseSensitive 更灵活）|
| =symbolScope=          | "all"          | workspace/symbol 搜索所有加载的包   |
| =importShortcut=       | "Both"         | import 语句支持跳转定义和文档        |

#+begin_src emacs-lisp
(use-package eglot
  :ensure nil                         ; 内置包，不需要安装
  :custom
  (eglot-request-timeout 120)        ; 大项目索引超时 30s → 120s
  (eglot-events-buffer-size 2000000)  ; 事件日志 2MB，出问题时用 M-x eglot-events-buffer 排查
  (eglot-autoshutdown nil)           ; 不自动关闭，用自定义函数管理资源
  (eglot-send-changes-idle-time 0.2) ; 同步代码延迟：默认 0.5s → 0.2s，快速送达 LSP
  (eglot-extend-to-xref t)           ; 关键：M-. 跳到依赖/标准库源码时复用当前 gopls
  :config
  ;; 注册 Go 语言服务器（支持多种模式）
  ;; 注意：这里使用列表形式，支持 go-ts-mode 和 go-mod-ts-mode
  (add-to-list 'eglot-server-programs
               '((go-ts-mode go-mod-ts-mode) . ("gopls")))
  
  ;; gopls workspace 配置
  ;; 文档：https://github.com/golang/tools/blob/master/gopls/doc/settings.md
  (setq-default eglot-workspace-configuration
                '(:gopls
                  ;; 排除无关目录（减少索引负担）
                  (:directoryFilters ["-**/node_modules" "-vendor" "-third_party" "-.git" "-grpc-go-examples"]
                   ;; 诊断延迟（平衡响应速度和性能）
                   :diagnosticsDelay "500ms"
                   ;; 补全设置
                   :completeUnimported t        ; 补全未导入的包
                   :deepCompletion t            ; 深度补全（可选）
                   :usePlaceholders t           ; 显示 ${1:arg}
                   :matcher "Fuzzy"             ; Fuzzy 匹配（推荐）
                   ;; 符号搜索范围
                   :symbolScope "all"           ; 搜索所有加载的包
                   ;; import 语句行为
                   :importShortcut "Both"       ; 支持跳转定义和文档
                   ;; 静态分析
                   :staticcheck t               ; 启用 staticcheck（可选）
                   :vulncheck "Off"             ; 漏洞检查（按需开启）
                   ;; 分析器
                   :analyses (:unusedparams t
                              :unusedwrite t
                              :shadow t))))
  
  ;; 注册其他语言服务器
  (add-to-list 'eglot-server-programs
               '(json-ts-mode . ("vscode-json-languageserver" "--stdio")))
  (add-to-list 'eglot-server-programs
               '(yaml-ts-mode . ("yaml-language-server" "--stdio")))
  (add-to-list 'eglot-server-programs
               '(lua-ts-mode . ("lua-language-server")))
  
  ;; ========== 资源管理：自动清理不再需要的 gopls 实例 ==========
  ;;
  ;; 问题：eglot-extend-to-xref 会让依赖库文件复用主项目的 gopls，
  ;; 但当关闭主项目 buffer 后，gopls 仍在运行，占用资源。
  ;;
  ;; 解决：在关闭 buffer 时检查：
  ;; 1. 当前 buffer 是否是通过 xref 打开的非项目文件
  ;; 2. 是否还有其他 buffer 在使用同一个 gopls 服务器
  ;; 3. 如果没有，则关闭该服务器，释放资源
  ;;
  (defun my/eglot-cleanup-xref-servers ()
    "清理不再需要的 xref 关联的服务器。
    
当关闭通过 xref 跳转打开的依赖库/标准库 buffer 时，
检查是否还有其他 buffer 在使用同一个 gopls 服务器。
如果没有，则关闭服务器，释放资源。"
    (when-let ((server (eglot-current-server)))
      ;; 检查当前 buffer 是否属于某个项目
      (let ((project (eglot--current-project)))
        ;; 如果当前 buffer 不属于任何项目（依赖库/标准库）
        ;; 且是通过 xref 打开的
        (unless (and project (project-root project))
          ;; 查找所有使用这个服务器的 buffer
          (let ((buffers-using-server
                 (cl-remove-if-not
                  (lambda (buf)
                    (with-current-buffer buf
                      (and (eglot-current-server)
                           (eq (eglot-current-server) server))))
                  (buffer-list))))
            ;; 如果只有当前 buffer 在使用，关闭服务器
            (when (= (length buffers-using-server) 1)
              (message "关闭不再使用的 gopls 服务器 (PID: %s)"
                       (process-id (jsonrpc--process server)))
              (eglot-shutdown server)))))))
  
  (add-hook 'kill-buffer-hook #'my/eglot-cleanup-xref-servers)
  
  ;; ========== 调试工具 ==========
  ;;
  ;; 检查 eglot-extend-to-xref 是否正常工作
  ;; 用法：M-x my/eglot-show-xref-servers
  ;;
  (defun my/eglot-show-xref-servers ()
    "显示当前所有 xref 关联的服务器。
    
用于调试 eglot-extend-to-xref 是否正常工作。
如果跳转到依赖库后此列表为空，说明 xref 机制未生效。"
    (interactive)
    (if (boundp 'eglot--servers-by-xrefed-file)
        (let ((count (hash-table-count eglot--servers-by-xrefed-file)))
          (message "Xref 关联的服务器数量: %d" count)
          (when (> count 0)
            (maphash
             (lambda (file server)
               (message "  %s -> PID:%s"
                        (file-name-nondirectory file)
                        (process-id (jsonrpc--process server))))
             eglot--servers-by-xrefed-file)))
      (message "eglot--servers-by-xrefed-file 未定义（eglot 可能未加载）"))))

* 终端（Eat）
:PROPERTIES:
:CUSTOM_ID: terminal
:END:

=Eat= 是一个纯 Elisp 实现的终端模拟器，不需要外部依赖。
和 =vterm= 相比：稍慢一点，但跨平台好、配置简单、和 Emacs 集成更自然。

Eat 有两种模式：
- Char 模式（默认）：键盘直接发送到终端，像普通终端
- Line 模式：可以像编辑普通 buffer 一样在终端输出里移动光标

按 =C-c C-k= 在两种模式间切换。

常用操作：
- =C-c t t= 在其他窗口打开 Eat
- 重复执行创建多个独立终端（=*eat*=, =*eat*<2>=, ...）

和 Emacs 的其他终端方案对比：

| 终端 | 原理 | 优点 | 缺点 |
|------+------+------+------|
| Eat | 纯 Elisp 模拟终端 | 跨平台、零外部依赖、和 Emacs 集成自然 | 极少数边缘情况下不如原生终端 |
| vterm | Emacs 模块 + libvterm (C) | 速度最快、终端兼容性最好 | 需要编译 C 模块、跨平台问题多 |
| eshell | Elisp 实现的 shell | 和 Elisp 深度集成、跨平台 | 不是真正的终端，不能跑全屏程序 |
| shell | comint-mode 包装系统 shell | 简单、内置 | 终端兼容性差（htop/vim 无法使用） |

**Eat 的使用场景：**
- 日常 =git=、=make=、=go build= 等命令行操作
- 用 Emacs 快捷键在终端里复制粘贴（=C-y= 直接粘贴）
- 终端输出可编辑（Line 模式下像普通 buffer 一样移动光标、选中文本）

**两种模式：**

| 模式 | 快捷键切换 | 行为 |
|------+-----------+------|
| Char 模式（默认） | =C-c C-k= → Line 模式 | 键盘输入直接发送给终端，像普通终端一样操作 |
| Line 模式 | =C-c C-k= → Char 模式 | 可以像编辑普通 buffer 一样在终端输出里移动光标、选中、复制 |

**配置说明：**
- =eat-shell=：指定终端里跑的 shell，默认不设时 Eat 用 =$SHELL= 环境变量
- =eat-kill-buffer-on-exit=：=exit= 后自动关闭终端 buffer，省去手动 =C-x k=
- =eat-cursor-type=：Char 模式下光标样式（=bar= 竖线、=box= 方块、=hollow= 空心）

**全局快捷键：**

| 快捷键 | 命令 | 做什么 |
|--------+------+--------|
| =C-c t t= | =eat-other-window= | 在另一个窗口打开 Eat |
| =C-c t n= | =eat= | 在当前窗口打开新的 Eat buffer |
| =C-c t p= | =my/eat-project= | 在项目根目录打开 Eat |

如果同一项目多次按 =C-c t t=，Eat 会复用已有的终端 buffer 而不是创建新的。
用 =C-c t n= 则每次创建一个新的独立终端实例。

#+begin_src emacs-lisp
(use-package eat
  :ensure t
  :custom
  (eat-kill-buffer-on-exit t)          ; exit 后自动关闭终端 buffer
  (eat-cursor-type 'bar)               ; Char 模式用竖线光标（和 Alacritty 习惯一致）
  :bind (:map eat-mode-map
         ;; Eat 内置了 C-c C-k 在 char/line 模式间切换，这里不覆盖
         )
  :config
  ;; 全局快捷键
  (global-set-key (kbd "C-c t t") 'eat-other-window)  ; 在另一个窗口打开终端
  (global-set-key (kbd "C-c t n") 'eat)               ; 在当前窗口打开终端
  ;; 在项目根目录打开终端
  (defun my/eat-project ()
    "在项目根目录打开 Eat 终端。"
    (interactive)
    (let ((default-directory (or (projectile-project-root)
                                 default-directory)))
      (eat-other-window)))
  (global-set-key (kbd "C-c t p") 'my/eat-project))
#+end_src

* Dired
:PROPERTIES:
:CUSTOM_ID: dired
:END:

=Dired= 是 Emacs 内置的文件管理器。几个关键的增强：

- =dired-dwim-target=：当有多个 Dired 窗口时，=C=（复制）和 =R=（重命名）
  的默认目标自动设为另一个窗口的目录。这就是"双面板文件管理器"体验。

- =dired-kill-when-opening-new-dired-buffer=： =a= 重新进入目录时复用当前 buffer，
  而不是开一堆 Dired buffer。

- 按 =C-x C-q= 进入 wdired 模式，可以像编辑文本一样批量改文件名。

- 标记文件后按 =Q= 可以在标记的文件中执行 =query-replace-regexp=，
  这是跨文件搜索替换最方便的方式。

* Local 配置（可选)
:PROPERTIES:
:CUSTOM_ID: local
:END:

如果将来有不想放进版本控制的个人配置（例如包含路径、密钥等），
可以放在 =lisp/init-local.el= 中，加入 =.gitignore=。

这个代码块在最后加载，所以 =init-local.el= 可以覆盖前面的任何设置。

#+begin_src emacs-lisp
;; 加载 gitignored 的个人额外配置（不在版本控制中的）
(let ((local-file (expand-file-name "lisp/init-local.el" user-emacs-directory)))
  (when (file-exists-p local-file)
    (load local-file)))
#+end_src
